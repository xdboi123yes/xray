# MDPI Peer-Review Revision, Minimal Research Codebase, and Track B Reproducible Release

## Problem Statement

The submitted MDPI *Diagnostics* manuscript on **TCR-P** received two peer-review reports: Reviewer 1 requested minor clarifications, notation definitions, enlarged Figure 2 legibility, and theoretical/experimental computational efficiency metrics; Reviewer 2 raised 15 detailed methodological, statistical, and reproducibility concerns covering **Tier 2** architecture ambiguity, **Patient-Disjoint Partition** leakage, diagnostic label inclusion/exclusion criteria, **Synthetic Augmentation Batch** provenance and quality evidence, **Validation Split** versus **Calibration Split** independence, **Adaptive Routing Threshold** pseudocode and arrival-order sensitivity, **Uncertainty Decomposition** (Monte Carlo Dropout vs. Test-Time Augmentation), 15-bin calibration diagnostics, split-conformal coverage utility, patient-clustered statistical comparisons with multiplicity control and effect sizes, tempered superiority claims over single-stage **Tier 1**, external CheXpert sample-size limitations, transparent latency/VRAM benchmarking, and full code/weight/version reproducibility.

An earlier cloud session produced a **Track A** manuscript revision and initial **Track B** pipeline upgrades, but critical blockers remain:

1. The Colab Pro L4 notebook fails during dependency installation on Python 3.13 due to legacy pinned API/UI/dev wheels.
2. Scientific protocol bugs remain in the **Track B** execution order: split-conformal quantile estimation runs before post-hoc temperature scaling without consuming temperature-scaled probabilities; synthetic generation sits after training with a hardcoded tiny batch cap and is disabled during **Tier 2** training.
3. Five bibliography entries from the submitted manuscript are unverified placeholders that must be audited and replaced with real, DOI-verified recent peer-reviewed publications.
4. The public repository currently mixes research code with 270+ files of unrelated web application, container, runner, and legacy journal boilerplate, and lacks a tagged public release hosting trained weights and frozen dependency versions.
5. Local workflow lacks CLI-driven Colab L4 execution for unattended monitoring, debugging, and artifact retrieval.

## Solution

Deliver an end-to-end, five-phase **Track B** revision and public reproducibility release (keeping **Track A** intact as an emergency fallback):

1. **Repository Split & Archive:** Preserve the full-stack web application, container definitions, remote runner scripts, and legacy journal files in a cleanly organized separate local archive repository, while pruning the public repository into a minimal, research-only layout tailored to the MDPI *Diagnostics* paper.
2. **Architectural Deepening:** Run a guided architectural review on the pruned research codebase to collapse shallow pass-through layers into a minimal, deep, well-tested Python package before running any expensive GPU experiments.
3. **Scientific & Python 3.13 Pipeline Fixes:** Resolve every protocol and environment blocker—lean Python 3.13 Colab dependencies preserving the runtime's PyTorch/CUDA/NumPy ABI, multi-batch resume-capable FID-gated synthetic generation wired ahead of **Tier 2** training, and strict causal ordering from **Validation Split** temperature scaling into **Calibration Split** conformal quantile estimation.
4. **CLI-Managed Colab Pro L4 Execution:** Configure local terminal management of Colab Pro L4 runtimes and execute the complete **Track B** patient-disjoint training, synthetic generation, ablation, calibration, external CheXpert, statistical, and latency/VRAM benchmark suite within the 400 compute-unit budget, gated by a SHA-256 provenance manifest.
5. **Manuscript Finalization & Public Release:** Update the MDPI manuscript (clean and blue-highlighted versions) and point-by-point response letter from the verified **Track B** outputs, replace all five unverified bibliography entries with real DOI-verified 2024–2026 peer-reviewed works, merge the verified work to the default branch, rewrite the repository overview for paper-first reproducibility, and publish a tagged GitHub Release containing trained model weights, frozen library versions, and SHA-256 checksums.

## Implementation Decisions

### 1. Repository Split and Minimal Layout
- Create a separate local archive repository containing the existing web application, container stack, remote runner scripts, documentation site config, and legacy Springer manuscript files, reorganized into a clean minimal structure so nothing is lost.
- Prune the public repository to a research-only layout consisting solely of configuration, a single consolidated Python package for the **TCR-P** domain, experiment/analysis scripts, the production and analysis notebooks, the MDPI manuscript package, tests, and a paper-first overview.
- Keep local agent configuration excluded from git tracking via local repository exclusion rules so the peer-review branch remains clean.

### 2. Architectural Deepening Before GPU Execution
- Run a structured architecture review on the pruned research codebase before launching **Track B** GPU execution, evaluating shallow pass-through wrappers across application, infrastructure, and core layers using the deletion test and deep-module principles.
- Consolidate approved deepening refactors into a cohesive package with minimal, stable interfaces so all tests, linters, and type checkers pass before recording the **Track B** provenance commit.

### 3. Colab Python 3.13 Environment and CLI Orchestration
- Introduce a dedicated lean Colab dependency specification containing only training, synthetic generation, evaluation, benchmarking, and figure packages with Python 3.13-compatible bounds while explicitly excluding web/API/UI/lint packages and preserving Colab's preinstalled PyTorch, CUDA, and NumPy ABI.
- Configure local Colab CLI tooling authenticated via Google OAuth to provision Colab Pro **L4** GPU runtimes (within the 400 compute-unit budget), mount Google Drive, run pipeline stages, stream logs, and retrieve generated artifacts and frozen environment manifests.

### 4. Causal Scientific Pipeline Fixes
- Enforce strict four-way **Patient-Disjoint Partition** reconstruction and verify zero pairwise patient overlap via a persisted split manifest before any downstream training or generation.
- Upgrade synthetic pneumothorax generation from a hardcoded 5-seed stub to a CLI-configurable, multi-batch, checkpoint/resume-capable pipeline iterating across all real **Patient-Disjoint Partition** training pneumothorax seeds (3 variations per seed), evaluating each batch against real training pneumothorax radiographs with an Inception-v3 FID $\le 50.0$ gate, logging every batch FID, and persisting accepted metadata and qualitative inspection grids.
- Reorder the production notebook so **Synthetic Augmentation Batch** generation runs before **Tier 2** training, and wire synthetic augmentation into the synthetic-enabled configurations while keeping the no-synthetic ablation (A8) strictly real-only.
- Reorder calibration so post-hoc temperature scaling ($T_{\text{cal}}$) fits exclusively on the **Validation Split** before split-conformal quantile ($\hat{q}$) calibration runs on the strictly disjoint **Calibration Split** using temperature-scaled probabilities.
- Preserve BatchNorm layers in evaluation mode during Monte Carlo Dropout, compute **Uncertainty Decomposition** via the Law of Total Variance, and run the complete $2 \times 2$ uncertainty ablation including TTA-only (A5b).
- Execute the full revision analysis suite: validation-only routing grid search, 10-seed arrival-order permutation plus adversarial drift-order sensitivity, 15-bin pre/post-temperature reliability diagnostics (ECE, class-wise ECE, Brier, NLL), conformal singleton/two-class/per-class coverage metrics, 2,000-iteration patient-clustered bootstrap with Holm–Bonferroni correction and Cohen's $h$ (including direct **Tier 1** vs. **TCR-P** comparison), expanded CheXpert zero-shot evaluation (A14b) with Wilson CIs, clinical FNR/threshold sweep, and CUDA-synchronized L4 latency/VRAM/FLOPs benchmarking.
- Gate pipeline completion on a provenance manifest recording the exact git commit, runtime/library versions, and SHA-256 hashes of all critical checkpoints and result tables.

### 5. Manuscript, Bibliography, and Public Release
- Anchor the **Track B** manuscript revision to the submitted MDPI baseline package and **Track A** revisions, updating all tables, figures (including print-legible 300-DPI Figure 2, reliability diagrams, and synthetic quality grid), in-text numbers, and the point-by-point reviewer response letter with verified **Track B** outputs while keeping **Track A** intact as a fallback.
- Audit the five flagged bibliography entries, replace every unverifiable entry with a real, DOI-verified 2024–2026 peer-reviewed publication matching each citation's scholarly role, and update corresponding in-text citations while maintaining $>40\%$ references from the past five years.
- Perform a full English grammar and clarity pass targeting long sentences and exact terminology alignment with the domain glossary.
- Merge the verified revision into the default branch, rewrite the repository overview as a paper-first reproducibility guide, and publish a tagged GitHub Release (`v1.0-mdpi-rev1`) attaching trained **Track B** weights, frozen library versions, and SHA-256 checksums.

## Testing Decisions

### What Makes a Good Test
- Tests verify observable external behavior, scientific invariants (zero patient overlap, variance additivity, calibration ordering, FID gating, resume idempotency), and statistical/artifact contracts through public module interfaces—never internal helper calls or brittle private attributes.
- All unit and integration tests run deterministically on CPU using tiny synthetic fixtures and lightweight fake adapters (no real Kaggle downloads, no real Stable Diffusion weights, no GPU required in CI).

### Seams and Modules Under Test
1. **End-to-End Research Pipeline Seam (highest seam, replacing the legacy FastAPI E2E test):** Exercises the full causal pipeline on a small patient-grouped dummy dataset—**Patient-Disjoint Partition** → mocked **Synthetic Augmentation Batch** → **Tier 1** and **Tier 2** training → **Validation Split** temperature scaling → temperature-scaled **Calibration Split** conformal $\hat{q}$ → **TCR-P** inference (**Escalation** and **Human Deferral**) → provenance manifest validation.
2. **Calibration, Uncertainty, Routing, and Statistics Seam:** Exercises **Uncertainty Decomposition** ($\sigma^2_{\text{MC}} + \sigma^2_{\text{TTA}} = \sigma^2_{\text{total}}$ and BatchNorm `eval()` preservation), 15-bin ECE / class-wise ECE / NLL / Brier / Wilson CI, patient-clustered bootstrap + Holm–Bonferroni + Cohen's $h$, **Adaptive Routing Threshold** deadband behavior, arrival-order sensitivity, and clinical threshold sweeps.
3. **Multi-Batch Synthetic Generation & Resume Seam:** Exercises multi-batch iteration over all training pneumothorax seeds, FID gate accept/reject persistence and FID logging, and crash-resume idempotency behind fake generator and fake FID adapters.
4. **Manuscript, Bibliography, and Release Verification Seam:** Verifies clean LaTeX compilation with zero undefined citations or cross-references, verified DOIs across the audited bibliography entries, Python 3.13 dry-run compatibility for the Colab dependency spec, and SHA-256 / git-commit parity between the provenance manifest and release assets.

### Prior Art
- Existing unit tests covering MDPI revision metrics, uncertainty decomposition, ablation specifications, routing behavior, dataset preprocessing, and statistical tests serve as the baseline suite and must stay green (at or above the project coverage threshold) throughout architectural deepening and bug fixes.
- Existing FastAPI/web tests move with the web application into the separate local archive repository.

## Out of Scope

- Deploying, hosting, or updating the archived web application, Docker images, or Windows/university remote runners beyond cleanly preserving them in the separate local archive repository.
- Obtaining prospective clinical validation or board-certified radiologist adjudication of synthetic radiographs (explicitly retained and transparently discussed as study limitations).
- Expanding the diagnostic task from binary pneumothorax screening to full 14-class multi-label thoracic pathology classification.
- Switching from split conformal prediction to adaptive conformal methods (APS/RAPS) beyond citing them as motivated future work.
- Provisioning A100 GPUs (unavailable on the user's Colab Pro tier; all GPU work targets **L4**).
